# 数据与连续性

制作时在项目工作目录维护一份结构化清单，格式可用 JSON 或清晰的数据表。数据属于当前项目，不写回 skill 安装目录。

## 最小字段

### 演员与角色

- `actor_id`、姓名、身高体重、肩胸腰臀、衣裤标码、鞋码、头发情况。缺项为空。
- `character_id`、角色名、对应 `actor_id`、现实／回忆／幻象阶段。
- 同演员饰演多个角色使用同一 `actor_id`；“过去的自己”等象征对应另写说明，不据此自动共用演员。

### 场次

- `scene_id`：包括续场子段，保持原剧本编号。
- `story_day_id`：现实故事日或回忆阶段。
- 地点、日夜、实际出镜角色、仅声音角色、动作中的换衣及污染。
- `basis`：剧本文字依据或“服装设计安排”。候选删改段落注明是否纳入当前方案。

### 造型

- `look_id`、`character_id`、阶段／故事日、`scene_ids`。
- 上装、下装、鞋、配饰、发型、妆面。
- `garment_ids`：实物标识。裤鞋复用、加外套形成新造型时共用原实物编号。
- 来源：演员自有／已有道具／另购／借用／待补。
- 状态：干净、自然旧、刻意做旧、污染、湿态；状态变化记录场号与部位。
- 备份件数和原因，独立于造型套数。
- 上装、下装、全身图三个位置，初始可为空。

## 计数规则

- **角色造型数**：该角色唯一 `look_id` 数量。
- **演员造型数**：该演员所有角色的唯一 `look_id` 数量。
- **实际备衣**：按 `garment_id` 去重，再加备份件数。无法准确拆分实物时用文字说明，不能编造总件数。
- **每天一套**：不同故事日给不同日常造型，同日连续场景保持一致。居家跨日复用需明确写在条目里。同日确有家居转外出时可以有两套。
- **污染递进**：同一造型的干净／落灰／加污可用状态记录，不自动增加 `look_id`。若为贴污染对照图增加区域，标为同套状态，不能多算造型。

## 两份产物的核对方法

从数据清单分别生成 PPT 和 Excel，不手工在两份文件各维护一套数字。若通过在线工具编辑 PPT，按清单逐项写入，并读回确认。

比较每个角色的 `(look_id, story_day_id, scene_ids)`。数量相等但场次不同也算冲突。输出版本标题／日期保持一致，已保存旧版不自动等于本次新方案。

典型检查：

- 回忆中的青年角色由主角演员饰演，角色分开、演员汇总合并。
- 儿童象征主角过去但另有儿童演员，演员统计分开。
- 白衬衫加一件制服形成第二种造型，实物不是两整套。
- 17场掌心血、18场干血是皮肤状态变化，未写衣物转印时不添加血衣采购。
- 群众人数未知时写“每人1套，人数待定”，用可复制空白条目，不用一条模板当作真实总人数。
